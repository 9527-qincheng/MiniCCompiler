## 0. 一句话说明为什么必须做

语法分析器**只消费 `TokenList`**。`Token` 里没有 `[` 这个类型，Parser 就**永远等不到它**——
再完备的预测分析表也匹配不上。因此**词法不扩充，整条挑战版链路无法启动**。

### 2.3 ⚠️ 关键提醒

**`<`、`>`、`!` 这三个单字符运算符当前也不存在**（现行 `ScanOperator` 只认 `+ - * / =` 和界符）。
所以不只是加双字符，**单字符运算符也要一并补齐**，且必须**先判断双字符、再回落单字符**。

### 2.4 建议的枚举最终形态

```cpp
enum class TokenType
{
    TOKEN_NONE = 0,
    /* 关键字（001~012） */
    TOKEN_INT, TOKEN_FLOAT, TOKEN_BOOL, TOKEN_CHAR, TOKEN_VOID,
    TOKEN_IF, TOKEN_ELSE, TOKEN_WHILE, TOKEN_PRINT, TOKEN_RETURN,
    TOKEN_TRUE, TOKEN_FALSE,
    /* 标识符 / 常量（051~054） */
    TOKEN_IDENT, TOKEN_NUM_INT, TOKEN_NUM_FLOAT, TOKEN_CHAR_CONST,
    TOKEN_STRING,                    // 保留为词法扩展（不进文法，见 §6）
    /* 界符（021~028） */
    TOKEN_LPAREN, TOKEN_RPAREN, TOKEN_LBRACE, TOKEN_RBRACE,
    TOKEN_LBRACKET, TOKEN_RBRACKET, TOKEN_SEMI, TOKEN_COMMA,
    /* 运算符（031~044） */
    TOKEN_PLUS, TOKEN_MINUS, TOKEN_MUL, TOKEN_DIV, TOKEN_ASSIGN,
    TOKEN_EQ, TOKEN_NE, TOKEN_LT, TOKEN_LE, TOKEN_GT, TOKEN_GE,
    TOKEN_AND, TOKEN_OR, TOKEN_NOT,
    /* 结束 */
    TOKEN_EOF
};
```

> **注意**：枚举**顺序可自定**，但**必须提供编码映射**（T3），因为预测分析表以**编码**为下标，不是枚举序号。

## 4. T3：编码映射函数（**关键，不可省**）

预测分析表的行列下标是**数字编码**（终结符 `001~099`），不是枚举序号。必须提供双向映射：

```cpp
// 建议置于 token.h 声明、token.cpp 实现
int       TokenTypeToCode(TokenType t);   // 例：TOKEN_INT -> 1
TokenType CodeToTokenType(int code);      // 例：26 -> TOKEN_RBRACKET
```

### 5.2 T6：`ScanOperator` 改双字符优先（**最易出错，务必按此顺序**）

**现行问题**：`ScanOperator` 是**单字符 switch**，`==` 会被拆成两个 `=`，`<=` 会被拆成 `<` + `=`。

**正确逻辑**（先看两位，再回落一位）：

```
入口：当前字符 ch = source[pos]
步骤 1：若 pos+1 < size，取 two = source[pos..pos+1]
步骤 2：查双字符表
        "==" → TOKEN_EQ     "!=" → TOKEN_NE     "<=" → TOKEN_LE
        ">=" → TOKEN_GE     "&&" → TOKEN_AND    "||" → TOKEN_OR
        命中则产出该类型、pos += 2、col += 2，返回
步骤 3：未命中双字符，查单字符表
        + - * / = < > ! ( ) { } [ ] ; ,
        命中则产出、pos += 1，返回
步骤 4：均未命中 → EmitError("unexpected character 'x'")，pos += 1，继续
```

### 5.3 ⚠️ 边界情况（必须处理）

| 输入 | 期望行为 |
|---|---|
| `a = b;` | 单个 `=` → `TOKEN_ASSIGN`（**不能**因为查双字符失败就丢失） |
| `if (a == b)` | `==` → `TOKEN_EQ`（**一个** Token，不是两个） |
| `a <= b` vs `a < = b` | 前者 `TOKEN_LE`；后者 `TOKEN_LT` + `TOKEN_ASSIGN`（按字符实际相邻判断） |
| `a = b != c` | `=` 单独成立，`!=` 成对成立 |
| `x &&& y` | `&&` → `TOKEN_AND`，剩余 `&` → **报错**（`&` 不是合法单字符） |
| `a << b` | `<<` 不是合法运算符：第一个 `<` → `TOKEN_LT`，第二个 `<` → `TOKEN_LT`（**不报错**，交给语法阶段报错） |
| 字符串 `"a==b"` 内 | 双字符**不生效**（字符串扫描独立处理） |
| 注释 `// a==b` 内 | 双字符**不生效**（注释跳过） |

> **判据**：`==` `!=` `<=` `>=` `&&` `||` **只有六个**双字符运算符。其余组合一律按单字符逐个产出。

### 5.4 T7：新增 `ScanCharConst`

**现行完全没有 `'` 的处理**，输入 `'a'` 会在 `ScanOperator` 走到 default 报错。

```
入口：当前字符为 '
步骤 1：记录起始行列号
步骤 2：跳过开头 '
步骤 3：若下一个字符是 \ ，读转义序列：
        \n → 换行(10)   \t → 制表(9)    \r → 回车(13)
        \0 → 空字符(0)  \\ → 反斜杠     \' → 单引号
        其他 → 报错「未知转义序列」
步骤 4：否则读单个字符
步骤 5：期望收尾 '
        是 → 产出 TOKEN_CHAR_CONST，m_cVal = 字符值，m_szContent = 原文（含引号）
        否 → EmitError("字符常量未闭合 或 多字符字符常量")，尽量恢复
```

**待决策**：`'ab'` 这类多字符常量——报错，还是只取首字符？**建议报错**（与 C 语义一致）。

## 6. 字符串常量的处置（**需先确认**）

| 项 | 现状 |
|---|---|
| 词法 | 现行**能识别** `"..."`，有 `TOKEN_STRING` |
| 文法 | 挑战版文法**没有字符串终结符**，`print` 只接受**表达式** |
| 后果 | `print("abc");` → 词法出 `TOKEN_STRING` → **语法阶段无产生式可匹配，报语法错误** |

**三个选项**（先确认再动手）：

- **A（当前默认，推荐）**：**保留**字符串词法能力，**不入文法**。文档已注明「字符串常量为词法扩展，挑战版文法不支持」。
  → **词法侧不用改**，仅需知晓 `print` 不支持字符串。
- **B**：**删除** `TOKEN_STRING` 与 `ScanString()`。风险：`tests/lex_test.mc` 含字符串内容，需同步改测试。
- **C**：**扩展文法**支持字符串字面量。代价：新增终结符 + 产生式 + 编码，**整套 First/Follow/Select 与预测分析表需重新生成**。

> **本文档按 A 编写**。若选 B/C，须先通知设计文档维护者重新生成表格。
