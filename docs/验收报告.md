### 3.2 `tests/test.mc` 五份产物实样

源码（3 行）：`int a;` / `float b;` / `a = b + 1;`

**`.token.txt`（14 个 Token）**

```
1:1  INT  int
1:5  IDENT  a
1:6  SEMI  ;
2:1  FLOAT  float
2:7  IDENT  b
2:8  SEMI  ;
3:1  IDENT  a
3:3  ASSIGN  =
3:5  IDENT  b
3:7  PLUS  +
3:9  NUM_INT  1
3:10  SEMI  ;
4:1  EOF  <eof>
```

**`.ast.txt`**（前序遍历 + 缩进 + `@行:列`）

```
Program  @1:1
  Decl(INT a)  @1:1
  Decl(FLOAT b)  @2:1
  Assign  @3:1
    Ident(a)  @3:1
    BinOp(PLUS)  @3:7
      Ident(b)  @3:5
      Num(1)  @3:9
```

**`.sym.txt`**（五节分表；Types 节由 `SymbolTable::RecBuiltinTypes()` 登记 5 个内建类型并给出字节宽度）

```
=== Symbol Table (scope 1) ===
-- Variables --
  a : INT  @line 1 scope 1
  b : FLOAT  @line 2 scope 1
-- Constants --
  1 : INT = 1  @line 3
-- Types --
  int : INT  size 4
  float : FLOAT  size 4
  bool : BOOL  size 4
  char : CHAR  size 1
  void : VOID  size 0
-- Procedures (challenge) --
-- Labels (challenge) --
```

**`.quad.txt`**（4 条，含两处显式类型转换）

```
(ITOF, 1, -, _T1)  @3:7
(ADD_4F, b, _T1, _T2)  @3:7
(FTOI, _T2, -, _T3)  @3:1
(ASSIGN_4, _T3, -, a)  @3:1
```

读法：`(ITOF, 1, -, _T1)` 是 int 常量 `1` 提升为 float；`(ADD_4F, b, _T1, _T2)` 是 float 相加（`ADD` 是表 5-2 的加法大类，`_4F` 是 32 位单精度后缀）；`(FTOI, _T2, -, _T3)` 是结果降回 int 赋给 `a`；`(ASSIGN_4, _T3, -, a)` 是赋值（4 字节）。

`(ITOF, 1, -, _T1)` 与 `(FTOI, _T2, -, _T3)` 证明：`float b` 参与运算后赋给 `int a`，中间代码层**确实**插入了双向类型转换，没有在目标代码里临时补救。

**`.asm`**（47 行，节选核心）

```asm
    .globl main
    .data
    .bss
    .align 8
a:
    .zero 8
    .align 8
b:
    .zero 8
    .text
main:
    pushq %rbp
    movq %rsp, %rbp
    subq $32, %rsp
    movl $1, %eax
    cvtsi2ss %eax, %xmm0
    movss %xmm0, -8(%rbp)
    movss b(%rip), %xmm0
    movss -8(%rbp), %xmm1
    addss %xmm1, %xmm0
    ...
    cvttss2si %xmm0, %eax
    ...
    xorl %eax, %eax
.Lret0:
    movq %rbp, %rsp
    popq %rbp
    ret
```

结构与四元式一一对应：`ITOF` → `cvtsi2ss`、`+` → `addss`、`FTOI` → `cvttss2si`、`=` → `movl`。

### 5.6 答辩前一轮「以代码为准」的加固（C 档十项）

验收口径定稿后又做了一轮体检，把能当场修掉的工程问题收掉。**十项全部有实测证据，

**① O(n²) 性能缺陷。** `CParser::RecordStep` 每步都拼「分析栈 + 剩余输入」字符串，
三个调用点、每 Token 至少 3 次，而这份轨迹只有 `--dump-parse` 用。
新增 `SetTraceEnabled(bool)`（默认关），`main.cpp` 只在要写 `.parse.txt` 时打开；
`Parse()` 的防死循环改用独立计数器。**1000 个空函数：68 150 ms → 189 ms（约 360 倍），
恢复线性（100/200/400/1000 分别 125/46/72/189 ms）**；`ll1_411.parse.txt` 逐字一致。

|---:|---:|---:|
| 100 | 357 ms | 125 ms |

| 400 | 4 425 ms | 72 ms |
| 1000 | **68 150 ms** | **189 ms** |

**② 四项静态检查**（新增 6 个用例，旧 19 个基线一字未改）：

| 检查 | 修之前 | 现在 |
|---|---|---|
| 数组名不带下标 | `b = a;` 静默取 `a[0]` | 报错 |
| 常量下标越界 | `int a[3]; a[5]=1;` 通过，运行读栈垃圾 | 报错 |
| 非 void 函数缺 return | 调用得 `0` | 警告（不拦编译） |

### 6.2 已知限制（README「已知限制」节，如实列出）

1. 支持 `++`/`--`（前后缀）；不支持 `+=`/`%`/`?:`/`for`/`do-while`/`break`/`continue`/`switch`/`goto`。
2. 不支持多维数组、字符串字面量的语义、逗号表达式、链式赋值、函数原型声明。
3. 顶层声明必须全部位于语句之前（`程序 → 声明部分 语句部分`，LL(1) 下不可逆）；**函数体/块内不受此限**。
4. 数组长度必须是整型常量。
5. `&&`/`||` 要求两侧为 `bool`；`char` 已按整型参与算术与关系运算（C 语义的整型提升，`bool` 仍不参与）。
6. 语义不检查：数组下标越界（实参个数与 `return` 类型已在语义阶段检查，见 5.3）。
7. 词法上 `1.` 合法、`.5` 非法。

> 以上限制**均在文法和语义层主动拦截**（给出带行列号的错误），不会静默生成错误代码——这是与"未实现"的本质区别。
