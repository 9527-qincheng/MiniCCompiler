### 2.3 🔴 为什么「只编译 symbol.cpp 能过」是个陷阱

```
g++ -c src/symbol/symbol.cpp   → 退出码 0 ✅（他大概就是这么自测的）
build.bat build（全工程）       → 退出码 1 ❌
```

新版 `symbol.h` 声明的 10 个函数（`RecVar`/`RecArray`/`RecConst`/`SearchVar`/`SearchConst`/`BackfillConst`/`CheckAssign`/`DumpSymTab`/`EnterScope`/`ExitScope`）在 `symbol.cpp` 中**全部有实现**——所以模块内部自洽。

**但他的自测只覆盖了自己那个模块，没有编译全工程。** 而两套测试脚本恰好**都躲开了这个雷**：

| 测试脚本 | 是否 `#include` symbol.h | 结果 |
|---|---|---|
| `run_grammar_selfcheck.ps1` | 否（只 include `parser/grammar.h`） | 退出码 0 ✅ |
| `run_parser_unit.ps1` | 否（只 include `lexer/lexer.h`、`parser/parser.h`） | 退出码 0 ✅ |

## 三、值得保留的部分 ✅

**必须肯定**：他这次的作用域栈设计**确实有价值**，而且**恰好命中了设计文档的要求**。

```cpp
// --------【内部改造：作用域栈，替换旧扁平数组】--------
std::vector<std::unordered_map<std::string, VarEntry>> m_varScopeStack;
int m_currentScopeLevel;
```

```cpp
// 【核心改造：自内向外查找，实现内层遮蔽外层】
const VarEntry* SymbolTable::SearchVar(const std::string& name) const
{
    for(auto it = m_varScopeStack.rbegin(); it != m_varScopeStack.rend(); ++it)
    {
        auto iter = it->find(name);
        if(iter != it->end()) return &iter->second;
    }
    return nullptr;
}
```

设计文档 §5.4 第 3 条写得清清楚楚：

> `SearchVarInfoTbl` 必须改为**按作用域链查找**（v3.1 为线性扫描，块作用域下会串名）

**他的实现方向完全正确**，`rbegin→rend` 的自内向外查找正是「内层遮蔽外层」的标准做法。另外 `RecArray`（数组登记）也是设计文档要求的挑战版功能。

**问题不在思路，在于他选择「推倒重写」而不是「移植进既有类」** —— 这正是上次沟通指南里的**路线 A vs 路线 B** 之别。
