### 3.2 代码改动 ✅ 正确且有效

**改动 1：跳过 UTF-8 BOM**（`src/lexer/lexer.cpp:88-96`）

```cpp
// 跳过 UTF-8 BOM（EF BB BF）：Windows 记事本/PS 保存的文件常带 BOM
if (m_szSource.size() >= 3 &&
    static_cast<unsigned char>(m_szSource[0]) == 0xEF &&
    static_cast<unsigned char>(m_szSource[1]) == 0xBB &&
    static_cast<unsigned char>(m_szSource[2]) == 0xBF)
{
    m_szSource.erase(0, 3);
}
```

**实测**：写入带 BOM 的 `int a;`（前 3 字节 `239 187 191`）→ 编译退出码 **0**，不在报错。✅
**必要性核实**：`origin/dev` 上的 `lexer.cpp` **不含**此逻辑 → 是真修复。

**改动 2：多字符常量不再产出 token**（`src/lexer/lexer.cpp`，`ScanCharConst()`）

...
// 出错则不产出 token（方案 B），让语法阶段自然发现缺失

**实测**：`char c = 'ab';` → 报 `multi-character char literal`，**不再产出伪 token**。✅

### 3.5 ⚠️ 缺陷 3：`.editorconfig` 有一行语法错误

新增 `.editorconfig`（12 行），第 10–12 行：

```ini
[*.mc]
charset = utf-8-bom = false
indent_style = tab
```

`charset = utf-8-bom = false` **不是合法的 EditorConfig 语法**。
`charset` 的合法取值只有 `latin1` / `utf-8` / `utf-8-bom` / `utf-16be` / `utf-16le`；
编辑器解析器会告警并忽略该行。

**看意图应是**「`.mc` 文件不带 BOM」，正确写法：

```ini
[*.mc]
charset = utf-8
indent_style = tab
```

（顺带：`indent_style = tab` 与 `.mc` 源文件的实际缩进习惯是否一致，也建议确认一下。）

## 六、审查环境说明（重要）

审查过程中发现一个**环境陷阱**，供后续复现参考：

`tests/run_parser_tests.ps1:114` 使用系统临时目录：

```powershell
$scratch = Join-Path ([System.IO.Path]::GetTempPath()) ("minic_parser_" + [System.Guid]::NewGuid().ToString("N"))
```

在受限环境下，`%TEMP%`（`C:\Users\<user>\AppData\Local\Temp`）**不可写**，
导致 41 个用例全部因 `cannot write output file` 而失败——**这是假失败，不是仓库缺陷**。

**规避**：把 `TEMP`/`TMP` 指向工作区内目录即可，随即全部通过：

```powershell
$env:TEMP='E:\计算机软件实训\_tmp'; $env:TMP=$env:TEMP
pwsh -File tests\run_parser_tests.ps1     # → All 41 passed
```

正常命令行环境下无此问题。
