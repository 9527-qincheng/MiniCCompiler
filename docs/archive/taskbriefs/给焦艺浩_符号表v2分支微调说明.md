## 二、两个细节做得很对，值得在组内推广

### 1. 作用域栈存下标，不存指针

```cpp
std::vector<std::unordered_map<std::string, std::size_t>> m_varScopeStack;
```

你在注释里写了理由：「`m_VarInfoTbl` 会 reallocate，而 `ir.cpp` 依赖扁平下标稳定」。

**这是真懂代码的写法。** 如果存 `VarEntry*`，`m_VarInfoTbl.push_back` 触发扩容后
所有已存指针全部失效，`ir.cpp` 按 `op.m_iLink` 回查时就会读到野内存。
存下标就完全避开了这个问题。

## 三、需要修改的 3 处

### ① 🟡 `tests/symbol_test.cpp:6` 触发 `-Wcomment` 警告

```
tests/symbol_test.cpp:6:1: warning: multi-line comment [-Wcomment]
    6 | //   g++ -std=c++17 -Isrc tests/symbol_test.cpp src/symbol/symbol.cpp \

```

原因：`//` 注释行**以反斜杠结尾**，会把下一行"续"进注释里。
项目要求零警告，改法二选一——去掉行尾的 `\`，或改用 `^`：

```cpp
//   g++ -std=c++17 -Isrc tests/symbol_test.cpp src/symbol/symbol.cpp ^
//       src/lexer/token.cpp src/sema/ir.cpp -o build/symbol_test.exe && build/symbol_test.exe
```

### ② 🟡 `RecVarTbl` 在"重名"路径会返回错误的下标（真缺陷）

```cpp
// src/symbol/symbol.cpp:207-215 （你现在的写法）
int SymbolTable::RecVarTbl(const std::string& name, TokenType type, int line)
{
    VarEntry* ve = RecVar(name, type, line, 0);
    if (!ve) return -1;
    return static_cast<int>(m_VarInfoTbl.size()) - 1;   // ← 问题在这
}
```

问题：`RecVar` 遇到重名时**不会 push_back**，而是返回已存在的那一项的指针。
此时 `m_VarInfoTbl.size() - 1` 指的是**最后一个元素**，不是重名的那一项
→ **返回错下标**。而 `ir.cpp` 正是按下标回查表项的，会用错对象。

你测试 ⑦ 只覆盖了不重名的路径，所以没暴露。

修法：用指针差算下标，两条路径都对——

```cpp
int SymbolTable::RecVarTbl(const std::string& name, TokenType type, int line)
{
    VarEntry* ve = RecVar(name, type, line, 0);
    return ve ? static_cast<int>(ve - m_VarInfoTbl.data()) : -1;
}
```

> 为什么这样安全：`ve` 一定指向 `m_VarInfoTbl` 内部的元素（要么是刚 push 的，
> 要么是已存在的），所以指针差就是合法下标。用 `data()` 做基准，
> 即使 `ve` 是 `nullptr` 也不会解引用（三元运算符先判空）。

**建议顺手补一条断言**，把这个修法锁住：

```cpp
// 重名路径：RecVarTbl 必须返回"已存在那一项"的下标，而不是最后一项
int i1 = sym.RecVarTbl("x", TokenType::TOKEN_INT, 1);
int i2 = sym.RecVarTbl("y", TokenType::TOKEN_INT, 2);
int i3 = sym.RecVarTbl("x", TokenType::TOKEN_INT, 3);   // 重名，不新增
assert(i3 == i1);                                       // 而不是 i2
```

### 2. `CheckAssign` 新增的告警是行为变更，组内要对齐

你新增了 `"suspicious assignment between A and B"` 告警。
dev 上只有 float→int 会告警，现在 `bool b = 1;` 这类也会告警。

方向是**正确**的（符合设计文档 §8.1 类型系统表），但要有心理准备：
这可能让某些既有用例的 stderr 多出新行。建议在 PR 描述里说明一句，
或至少在 `--dump-symtab` 的黄金基线里体现出来。

### 3. 常量表暂不参与作用域链

`m_ConstInfoTbl` 仍是扁平的，块内常量退出作用域后仍可查到。
当前用例不受影响，记为已知限制即可，不用现在改。

### 4. `SearchConstInfoTbl` 仍是线性扫描

常量语义上是全局的，线性扫描可接受。如果以后想统一风格再改，不影响这一版。
