## 三、分支 A：`SHB6667-patch-1` —— 不合入

### 3.1 最严重问题：文件放错位置 → 完全不参与构建 → 假绿灯

6 个新增文件**全部丢在仓库根目录**，而不是 `src/`、`tests/`：

```
bad_redecl.mc (16 B)        basic_sema_test.mc (69 B)
bad_undeclared.mc (18 B)    warn_float2int.mc (29 B)
sema_impl.cpp (4200 B)      semantic.h (2430 B)
```

`build.bat` 只递归收集 `src/` 下的 `.cpp`（`set "SRCDIR=%ROOT%src"` + `for /r "%SRCDIR%"`）：

```
Source dir : ...\shb\src

```

因此 `build.bat build` 打印 **BUILD SUCCESS（退出码 0）**，`build.bat test` 打印 **ALL TEST SUITES PASSED（退出码 0）** —— **全是假绿灯**。`git grep` 确认 `semantic.h` / `sema_impl` 在 `src/` 与 `tests/` 下 **0 处引用**，是彻底的孤儿文件。

### 3.2 把文件放对位置后：45 个编译错误

将 `semantic.h` / `sema_impl.cpp` 复制进 `src/symbol/` 并把 include 改为仓库真实路径后编译 → **45 个 error，退出码 1**：

```
error: 'TOKEN_EOF' was not declared in this scope; did you mean 'TokenType::TOKEN_EOF'?
error: 'Program' is not a member of 'ASTNodeKind'          ← 同 DeclList/StmtList/Decl/Assign/Ident/Op/Num/If/While/FuncDef/Call/Array/Expr
error: 'class NumNode' has no member named 'm_type'
```

根因是用了**已废弃的 v3.1 AST API**：

| 代码里写的（v3.1 旧 API） | 仓库现状（阶段⑤ 重构后） |
|---|---|
| `ASTNodeKind::Program` / `DeclList` / `StmtList` / `Op` / `Expr` | `AST_NODE_*` 共 19 项；**无** `DeclList`/`StmtList`/`Op`/`Expr` |
| `m_left` / `m_right` | `std::vector<ASTNodePtr> m_children` |
| `TOKEN_EOF`（无限定） | `TokenType::TOKEN_EOF`（enum class） |
| `NumNode::m_type` | 不存在该成员 |

另：`sema_impl.cpp` 里 `#include "common/error.h"` —— **仓库根本没有 `src/common/` 目录**；`EmitError` 实际声明在 `src/lexer/token.h:121`、定义在 `src/lexer/token.cpp:178`。

还有 `semantic.h` 自己的注释写着「放置位置：`src/symbol/semantic.h`」，与实际丢在根目录**自相矛盾**。
