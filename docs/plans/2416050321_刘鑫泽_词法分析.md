## 一、任务目标

按设计文档 §4.1 的终结符表实现挑战版词法分析器，把源文件切成 Token 序列，做到：

1. **17 个新增终结符全部产出**：`bool` / `char` / `print` / `true` / `false` / `[]` /
   六种关系运算符（`< <= > >= == !=`）/ 两种逻辑运算符（`&& ||`）/ 逻辑非 `!` / 字符常量。
2. **双字符运算符优先**：`==` 不能被拆成两个 `=`，`<=` 不能被拆成 `<` 和 `=`；
   反过来 `<` `>` `!` 也不能被双字符规则吞掉。
3. **字符常量与转义**：`'x'`、`'\n'`、`'\''`、`'\\'` 都要正确识别；多字符常量（`'ab'`）
   必须报错且**不产出伪 token**（否则下游会拿到一个不存在的终结符）。
4. **错误恢复**：未知转义、未闭合字符常量要报错并带行列号，但不能崩，后续 token 继续产出。
5. **编码健壮性**：UTF-8 BOM（`EF BB BF`）必须跳过，否则文件首字符会变成非法 token。
6. **常量登记**：整型 / 实型 / 字符 / 布尔四类常量登记进常量表，`Token::m_iConstIdx` 记录位序，
   供语法阶段的 `NumNode::m_iConstIdx` 透传。
