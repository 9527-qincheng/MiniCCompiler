### 🔴 问题 3：五个语义处理缺陷（我接线后实测出来的）

为了验证代码本身对不对，我在 worktree 里手动接线（`#include "sema/semantic.h"` + 把 TODO 换成 `{ SemanticAnalyzer sema(symtab); sema.Analyze(root); }`），然后逐项实测。**接线后符号表立刻有内容了**，但暴露出五个缺陷：

#### 缺陷 3.1 — `FuncDef` / `Param` 完全没处理，函数体里的东西全丢

`sema_impl.cpp` 的 `switch(node->m_kind)` 里**没有 `AST_NODE_FUNCDEF` 和 `AST_NODE_PARAM` 分支**（`git grep AST_NODE_FUNCDEF` 在该文件零命中），落到 `default: return TOKEN_EOF;`。

实测 `f2.mc`（只有函数定义）：
```c
int add(int x, int y) {
  int s;
  s = x + y;
  return s;
}
```
符号表输出：**五个分节全空**。`add`、`x`、`y`、`s` 一个都没登记。

实测 `fn.mc`（函数定义 + 调用）：
```c
int g;
int add(int x, int y) { ... }
g = add(1, 2);
```
```
minic: error: 7:5: undefined identifier add     ← 函数自己没登记，调用它当然找不到
```

**这会让所有带函数的用例全部误报**。语法组刚做完的 `func_def.mc`、`tests/parser/` 下若干函数用例都会挂。

#### 缺陷 3.2 — 关系运算结果类型推成 INT，应为 BOOL

`DeduceBinOp` 完全忽略第一个参数 `op`（签名里连参数名都省了：`TokenType DeduceBinOp(TokenType, TokenType lt, TokenType rt, ...)`），只做 `Promote(lt, rt)`。

于是 `a < 1`（INT 与 INT）推出 **INT**，而设计文档 §8.1 明确规定：

| 操作符 | 操作数1类型 | 操作数2类型 | 结果类型 |
|---|---|---|---|
| 关系运算 | T_INT | T_INT | **T_BOOL** |
| 关系运算 | T_FLOAT | T_FLOAT | **T_BOOL** |

实测 `r1.mc`：
```c
int a;
bool b;
b = (a < 1);
```
```
minic: warning: 3:1: suspicious assignment between BOOL and INT
```
`b` 是 BOOL，`a < 1` 被当成 INT，于是**本该正确的赋值报了假告警**。

#### 缺陷 3.3 — `&&` / `||` / `!` 直接报错

`DeduceBinOp` 只认 `IsNumeric()`（INT/FLOAT），遇到 BOOL 操作数就 `EmitError("operands must be numeric")`。

实测 `r2.mc`：
```c
bool x;
bool y;
bool z;
z = x && y;
```
```
minic: error: 4:7: operands must be numeric
minic: 1 error(s) found, compilation failed
```

设计文档 §8.1 明确 `&& ||` 要求 BOOL 且结果 BOOL。**现在是合法的挑战版程序被拒。**

#### 缺陷 3.4 — 一元节点 `AST_NODE_UNOP` 没处理

switch 里只有 `AST_NODE_BINOP`，**没有 `AST_NODE_UNOP`**。取负 `-x`、逻辑非 `!b` 落到 `default`，既不检查也不推导类型。

实测 `r3.mc`（`a = -q;`，`q` 未声明）：
```
minic: compilation finished (skeleton demo)
exit=0
```
**用未声明的变量做取负，一声不响地通过了。** 设计文档 §8.1 对 `-`（取负，INT→INT / FLOAT→FLOAT）和 `!`（BOOL→BOOL）都有明确规定。

#### 缺陷 3.5 — 数组不走 `RecArray`，维度信息丢失，且数组赋值报「invalid lvalue」

`VisitDecl` 无条件调 `RecVar`，`RecArray` 在该文件零命中。`AST_NODE_ARRAYDECL` 只被放进「安全遍历子节点」那一组，于是 `Decl(INT arr)` 被当普通变量登记，**`m_bIsArray` 恒为 false、`m_iArraySize` 恒为 0**。

实测 `arr2.mc`：
```c
int arr[10];
int y;
arr[0] = 1;
y = arr[0];
```
符号表里 `arr : INT`（没有数组标记），只有 2 条变量记录，`Constants`/`Types` 全空；而 `arr[0] = 1;` 直接报：
```
minic: error: 3:1: invalid lvalue
```

`VisitAssign` 只认 `AST_NODE_IDENT` 作为左值，**`AST_NODE_INDEX`（数组元素）被当成非法左值拒掉了**。挑战版的数组赋值全都是这种形式，等于整条数组特性不可用。

## 四、另外三处值得改但不阻塞

### 4.1 块作用域没有进出，`if`/`while` 的 `{}` 不隔离

实测 `sc.mc`：
```c
int a;
a = 1;
if (a > 0) {
  int t;
  t = 5;
}
a = t;              // t 已出块，应该报 undefined
```
```
minic: compilation finished (skeleton demo)     ← 没报错，块作用域没生效
exit=0
```

`Analyze()` 只在整个程序外面调了一次 `EnterScope(SCOPE_GLOBAL)` / `ExitScope()`，**`AST_NODE_BLOCK` 分支只遍历子节点，没有成对的 `EnterScope(SCOPE_BLOCK)` / `ExitScope()`**。

连带后果实测 `sc2.mc`（块内重名 `int a;` 遮蔽外层 `a`）：
```
minic: error: 4:3: duplicate variable 'a'      ← 内层遮蔽外层被误判成重复声明
```
而设计文档 §5.4 第 3 条明确要求「按作用域链查找，v3.1 线性扫描在块作用域下会串名」，v2 符号表分支（`bccd313`）已经把作用域栈做好了 —— **语义侧没用上**。

### 4.2 常量表基本是空的

词法的 `m_iConstIdx` 是**词法自己的 `m_ConstTexts` 下标**，而符号表 `m_ConstInfoTbl` 是另一个空表，两者没有对齐。所以：

- `VisitNum` 里 `if (num->m_iConstIdx >= 0)` 分支走 `BackfillConst(idx, ...)`，但符号表里没有对应下标 → `BackfillConst` 里 `if (iConstIdx >= m_ConstInfoTbl.size()) return;` **静默返回**。
- 只有 `else` 分支（字符/布尔常量）走 `RecConstTbl`，确实登记上了。

实测 `sema_basic.mc`（含 `1`、`2`、`3.5` 三个数字常量）：
```
-- Constants --              ← 全空
```
实测 `cb.mc`（`f = true; c = 'x';`）：
```
-- Constants --
  <anon> : BOOL = 0  @line 0     ← 登记上了，但名字、行号都是空/0
  <anon> : CHAR = 0  @line 0
```

`RecConstTbl("", type)` 传空名字，`m_iLine` 也没设（恒 0）。验收指南要求符号表的 Constants 节能看出常量值，**现在看不出。**

修改方向：`VisitNum` 统一走「语义阶段自己登记」—— 用 `RecConstTbl(文本, 类型)` 建新表项，把返回值赋回 `num->m_iConstIdx`，不要指望词法下标。数字常量的文本可以从 `NumNode` 的 `m_fValue` 格式化得到。这也是验收指南 §2.3「常量回填」能过的唯一路径。

### 4.3 `sema_impl.cpp` 带 UTF-8 BOM

```
semantic.h         BOM=False  size=2430  LF 46
sema_impl.cpp      BOM=True   size=5233  LF 139      ← BOM
sema_basic.mc      BOM=False  size=69    LF 7
```

仓库现在**全库带 BOM 的文本文件数为 0**，这个文件会是唯一的例外。词法器已经能跳过源文件 BOM（`lexer.cpp` `OpenSource`），所以不阻塞编译，但会破坏「全库无 BOM」的一致性。修法：用 VS Code「以 UTF-8 编码保存」或 `Set-Content -Encoding utf8NoBOM`。

## 七、给陕海波的整改要求

按优先级排，前四条是阻断项：

1. **改用 git 命令行**（这是根本）：`git clone` → `git checkout -b feature/sema origin/dev` → 在本地把文件放进 `src/sema/` → `build.bat list` 确认 `Total` 变成 10 → `build.bat build` → `git add -A && git commit -m "feat(sema): ..."` → `git push -u origin feature/sema`。网页版 `Add files via upload` 建不了子目录，这条路必须放弃。

3. **接线 `src/main.cpp:179`**：把 TODO 换成
   ```cpp
   { SemanticAnalyzer sema(symtab); sema.Analyze(root); }
   ```
   并在文件头 `#include "sema/semantic.h"`。
4. **补 `FUNCDEF` / `PARAM` 分支**：`FuncDef` 要登记函数名（`RecVar` 或单独的函数表）、对其 `Block` 子节点 `EnterScope(SCOPE_FUNCTION)`、遍历参数与函数体、`ExitScope()`。不补这条，所有带函数的用例全挂。
5. **`DeduceBinOp` 用上 `op` 参数**：关系运算 `== != < <= > >=` → 结果 `TOKEN_BOOL`；逻辑运算 `&& ||` → 要求两侧 BOOL、结果 BOOL；算术运算维持现有 `Promote`。
6. **补 `UNOP` 分支**：`-` 作用于 INT/FLOAT → 返回同类型；`!` 作用于 BOOL → 返回 BOOL；操作数不是数值/布尔时报错。
7. **`ARRAYDECL` 走 `RecArray`，`INDEX` 允许做左值**：`VisitAssign` 里把 `lhs->m_kind == AST_NODE_IDENT` 改成 `IDENT || INDEX`，索引节点要递归检查基址已声明、下标是整型。
8. **`BLOCK` 进出块作用域**：`AST_NODE_BLOCK` 分支里成对 `EnterScope(ScopeType::SCOPE_BLOCK)` / `ExitScope()`（注意：`FuncDef` 的 `Block` 已经是函数作用域，别重复进）。补完后 `sc.mc` 的 `a = t;` 必须报 undefined、`sc2.mc` 的内层遮蔽必须不再报重复。
