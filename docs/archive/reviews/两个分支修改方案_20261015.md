## 一、分支 A：`SHB6667-patch-1` —— 重做方案

### 1.1 为什么必须重做

分支 A 不是"有小毛病"，而是**根本没有被编译过**：

```
build.bat list  →  File count : 9        ← 他那 2 个 .cpp 根本不在里面
build.bat build →  BUILD SUCCESS
build.bat test  →  ALL TEST SUITES PASSED   ← 全是假绿灯
```

`build.bat` 只自动收集 `src/**/*.cpp`，而这 6 个新文件**全部丢在仓库根目录**（`bad_redecl.mc`、
`basic_sema_test.mc`、`sema_impl.cpp`、`semantic.h`、`warn_float2int.mc`、`bad_undeclared.mc`），
所以它们既没进编译器、也没进测试。他自己在 `semantic.h` 里写的注释是
「放置位置：`src/symbol/semantic.h`」，**与实际位置自相矛盾**。

把文件归位（并修好 include）后真编译：`g++ -std=c++17 -Wall -Wextra -Isrc -fsyntax-only src/sema/semantic.cpp`
→ **退出码 1，45 个 error**。

| 节点 | `m_children` 约定 | 关键字段 |

**Step 4 —— 类型推导用一个私有小工具统一出口（解决 `TOKEN_*_CONST` 乱用）**

```cpp
// 把 NumNode 的字面量种类映射成「类型」，全程只用这 4 个值：
// TOKEN_INT / TOKEN_FLOAT / TOKEN_CHAR / TOKEN_BOOL
TokenType SemanticAnalyzer::NumType(const NumNode* n) const
{
    if (n->m_bIsFloat) return TokenType::TOKEN_FLOAT;
    if (n->m_isChar)   return TokenType::TOKEN_CHAR;
    if (n->m_isBool)   return TokenType::TOKEN_BOOL;
    return TokenType::TOKEN_INT;
}
```

这样 `IsNumeric` / `Promote` / `DeduceBinOp` 里就不会再出现 `TOKEN_INT_CONST`，
`VarEntry::m_type` 与表达式类型也就能直接比对了。类型系统表见设计文档 §8.1（14 条规则）。

**Step 5 —— 查重要交给符号表，不要重复报错**

原代码 `VisitDecl` 里自己 `SearchVar` 报一次"redefinition"，然后调 `RecVar` 又报一次
"duplicate variable"——**同一个错误打印两条**。而且 `SearchVar` 是**按作用域链**查的，
用它查重会导致内层无法遮蔽外层（违反 C 语义，也正是分支 B 特意修掉的点）。

正确做法：

```cpp
void SemanticAnalyzer::VisitDecl(DeclNode* d)
{
    // RecVar 内部已做「当前作用域」查重并 EmitError，直接用它
    VarEntry* e = m_symtab.RecVar(d->m_szName, d->m_type, d->m_loc.m_iRow, d->m_loc.m_iCol);
    if (e) d->m_iSymIdx = static_cast<int>(e - m_symtab.m_VarInfoTbl.data());
}
```

`ARRAYDECL` 走 `RecArray(name, type, size, line, col)`（分支 B 刚加的接口）。
数组下标 `INDEX` 还要检查下标是整型（任务书 4.2 检查项）。

**Step 6 —— 常量回填（Q12）+ 字符/布尔常量自登记**

注意 `docs/interface.md` 第 9 条已登记：`'x'` / `true` / `false` 的 `Token::m_iConstIdx` 为 **-1**，
词法没有登记，**语义阶段 semantic003 要自己登记**。

```cpp
void SemanticAnalyzer::VisitNum(NumNode* n)
{
    TokenType t = NumType(n);
    if (n->m_iConstIdx >= 0)
        m_symtab.BackfillConst(n->m_iConstIdx, std::string(), t);   // 词法已登记 → 回填
    else

}
```

核心实现（`src/symbol/symbol.cpp`）：

```cpp
// 构造即建全局作用域（层级 1），永不弹出
SymbolTable::SymbolTable() : ... { m_varScopeStack.emplace_back();
                                    m_scopeTypeStack.push_back(ScopeType::SCOPE_GLOBAL); }

// 自内向外查找，先命中先返回（内层遮蔽外层）
VarEntry* SymbolTable::SearchVarInfoTbl(const std::string& name)
{
    for (auto it = m_varScopeStack.rbegin(); it != m_varScopeStack.rend(); ++it) {
        auto found = it->find(name);
        if (found != it->end()) return &m_VarInfoTbl[found->second];
    }
    return nullptr;
}
```

两个细节做得很对，值得表扬并在组内推广：
- **存下标而不是指针**（`std::vector<std::unordered_map<std::string, std::size_t>>`），
  注释写明理由「`m_VarInfoTbl` 会 reallocate，而 `ir.cpp` 依赖扁平下标稳定」——这是真懂代码。
- **查重只看当前作用域**（用 `curMap.find(name)` 而非 `SearchVarInfoTbl`），
  否则内层永远无法遮蔽外层。注释也写清了这个理由。

还自带 `tests/symbol_test.cpp`（8 组断言）+ `tests/run_symbol_tests.ps1`，并挂进了 `build.bat test`。

### 2.2 需要修改的 3 处

**① 🟡 `tests/symbol_test.cpp:6` 触发 `-Wcomment` 警告**

```
tests/symbol_test.cpp:6:1: warning: multi-line comment [-Wcomment]
    6 | //   g++ -std=c++17 -Isrc tests/symbol_test.cpp src/symbol/symbol.cpp \
      | ^
```

`//` 注释行**以反斜杠结尾**会把下一行"续"进注释。改成去掉行尾 `\`，或写成 ` ^`：

```cpp
//   g++ -std=c++17 -Isrc tests/symbol_test.cpp src/symbol/symbol.cpp ^
//       src/lexer/token.cpp src/sema/ir.cpp -o build/symbol_test.exe && build/symbol_test.exe
```

**② 🟡 `RecVarTbl` 在"重名"路径会返回错误的下标**（真缺陷，实测确认）

```cpp
// src/symbol/symbol.cpp:207-215 （分支 B 现状）
int SymbolTable::RecVarTbl(const std::string& name, TokenType type, int line)
{
    VarEntry* ve = RecVar(name, type, line, 0);
    if (!ve) return -1;
    return static_cast<int>(m_VarInfoTbl.size()) - 1;   // ← 问题在这
}
```

重名时 `RecVar` **不会 push_back**，而是返回已存在的表项指针，
此时 `size() - 1` 指的是**最后一个元素**，不是重名那个 → 返回错下标，而 `ir.cpp` 正是按下标回查的。
分支 B 自己的测试 ⑦ 只测了不重名的路径，所以没暴露。

修法（用指针差算下标，两条路径都对）：

```cpp
int SymbolTable::RecVarTbl(const std::string& name, TokenType type, int line)
{
    VarEntry* ve = RecVar(name, type, line, 0);
    return ve ? static_cast<int>(ve - m_VarInfoTbl.data()) : -1;
}
```

**③ 🟡 `docs/interface.md` 未同步新接口**

`RecArray` 与 `SCOPE_BLOCK` 是新增的公开接口，按项目惯例（该文件"三、冲突记录"已记到第 10 条）
必须追加一条。现成文本可原样用：

```markdown
11. **符号表新增 `RecArray` 与 `SCOPE_BLOCK`**（阶段⑥ 符号表模块，2026-10-15）：
    设计文档 §5.4【变更】要求变量表项支持数组维度、作用域增加块级。
    变更内容：`ScopeType` 增 `SCOPE_BLOCK`；`VarEntry` 增 `m_bIsArray`/`m_iArraySize`；
    新增 `VarEntry* RecArray(name, type, size, line, col)`；`SearchVarInfoTbl` 由线性扫描改为
    **按作用域链自内向外查找**（内层可遮蔽外层）；`RecVar` 查重范围收窄为**当前作用域**；
    `CheckAssign` 扩展 char↔int、同类型，其余组合改为告警不阻断。
    兼容性：**未删除任何既有公开接口**，`m_VarInfoTbl` 仍为 public 且下标语义不变。
```

### 2.3 建议（不阻塞合入，可另开任务）

- `RecArray` 在 `src/` 下**没有调用点**（`git grep RecArray` 只命中 `symbol.h/.cpp` 自己）。

- `CheckAssign` 新增的 `"suspicious assignment between A and B"` 告警属于**行为变更**：
  dev 上只有 float→int 会告警，现在 `bool b = 1;` 这类也会告警。方向正确（符合 §8.1），
  但建议组内对齐后再定，或至少让它在 `--dump-symtab` 的黄金基线里被显式记录下来。
- 常量表（`m_ConstInfoTbl`）目前**不参与作用域链**，块内常量退出作用域后仍可查到。
  暂不影响当前用例，记为已知限制。
- `SearchConstInfoTbl` 仍是线性扫描。常量语义上是全局的，可接受；如要统一风格可后续再改。
