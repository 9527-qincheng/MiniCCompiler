## 2. MiniC 语言规格（挑战版）

### 2.1 课程最低规格范围（PPT 硬性约束，全部保留）

| 项目 | 内容 |
|---|---|
| 语言定位 | ANSI C 的子集 |
| 变量声明 | 全局变量声明，类型 `int`、`float` |
| 语句 | 赋值语句 |
| 表达式 | 算术表达式 `+ - * /` 及括号 |

### 2.2 挑战版扩展规格（本题采用全量）

| 编号 | 特性 | 说明 |
|---|---|---|
| C1 | 数据类型扩展 | 新增 `bool`、`char` 基本类型；支持 `int[]` 一维数组 |
| C2 | 流程控制与输出 | `if` / `if-else` 条件语句、`while` 循环、`print` 标准输出 |
| C3 | 运算能力升级 | 全套关系运算 `== != < <= > >=`；逻辑运算 `&&` `||` `!`；自增自减 `++` `--`（前缀与后缀，`b = a++` 取旧值、`b = ++a` 取新值） |
| C4 | 工程化进阶 | 块作用域（复合语句）、函数定义与调用、`return`、语法错误优雅恢复、常量折叠 |

**挑战版示例程序**（PPT 原文）：

```c
int a;
bool flag;
flag = a > 0 && a < 10;
if (flag) print(a); else print(0);
while (a > 0) { a = a - 1; }
```

### 2.3 必交交付物（PPT 硬性约束）

1. **Token 序列**（词法分析输出）；
2. **AST 语法树**（语法分析输出）；
3. **符号表**（语义分析期间构建）；
4. **四元式**（中间代码输出）。

v4.0 追加交付物：**挑战版文法、First/Follow/Select 集合、预测分析表、语法分析过程**。

### 2.4 工程约束

- 开发语言：**C++17 + CMake**；
- 模块接口冻结（PPT「接口先行」原则），变更需全员评审；
- 汇编产物后缀固定 `.asm`。

## 3. 编译器总体架构

### 3.1 五阶段流水线

```
源程序 → 词法分析 → 语法分析(LL(1)预测分析) → 语义分析(符号表) → 中间代码(四元式) →[挑战版] 目标代码(x86)
         CLex        CParser                 SymbolTable        IRGenerator            CCodeGen
```

语法分析阶段内部：`Token 流 → 预测分析驱动器（分析栈 + 预测分析表）→ 推导树 → 抽象语法树 AST`，
语义动作（semanticNNN）在推导过程中于对应位置执行。

### 3.2 模块职责与依赖

| 模块 | 输入 | 输出 | 依赖 |
|---|---|---|---|
| 词法分析 CLex | 源文件字符流 | `TokenList` + 常量登记 | 关键字表、字符分类表 |
| 语法分析 CParser | `TokenList` | AST + 语义动作触发 | 文法表、First/Follow/Select、预测分析表、错误输出 |
| 语义/符号表 SymbolTable | AST | 多表符号表、类型检查 | 语法、符号表 |
| 中间代码 IRGenerator | AST + 符号表 | `CodeList`（四元式） | 语义、符号表、类型系统表 |
| 目标代码 CCodeGen | `CodeList` | 汇编文本 | 中间代码、指令模板 |

### 3.3 数据传递链

| 阶段 | 数据载体 | 生产者 → 消费者 |
|---|---|---|
| 词法 → 语法 | `TokenList`（`vector<Token>`） | CLex → CParser |
| 语法 → 语义 | `ASTNodePtr`（基类 + 派生类树） | CParser → SymbolTable / IRGenerator |
| 语义 → 中间代码 | 符号表查询结果 + 类型系统表 | SymbolTable → IRGenerator |
| 中间代码 → 目标代码 | `CodeList`（`vector<Quad>`） | IRGenerator → CCodeGen |

### 4.3 挑战版文法（105 条产生式）

设计要点：

- 全程**无左递归**；
- 重复结构（声明列表、语句列表、形参列表、实参列表、表达式后缀）统一改写为 `X → ... X1`、`X1 → op ... X1 | ε` 的**右递归**形式，保证 LL(1)；
- 表达式按优先级分 9 层：`表达式 → 或 → 与 → 相等 → 关系 → 加法 → 乘法 → 一元 → 后缀 → 基本`（`相等` 层承载 `==`/`!=`，`关系` 层承载 `<`/`<=`/`>`/`>=`，与 C++ 的分层一致）；
- `++`/`--`（产生式 93–102）按**位置**分挂三处：前缀挂「一元表达式」（93/94，与一元 `-` 同层）、后缀挂「后缀表达式1」（95/96，与 `[]` `()` 同层）、单独成句挂「标识符后续」与「语句」「赋值」（97–102），因此**不新增非终结符**、不改变既有优先级层次；
- `if (...) 语句 [else 语句]` 的**悬挂 else** 为 LL(1) 固有二义，由预测分析表消解（见 §4.8）。

### 4.8 LL(1) 判定与冲突消解

**判定规则**：对同一非终结符 A 的任意两条不同产生式 `A→α`、`A→β`，须满足
`SELECT(A→α) ∩ SELECT(A→β) = ∅`。

**校验结果**：

- 除 `否则部分` 外，其余全部非终结符的 SELECT 集**两两不相交**；
- 唯一冲突：`否则部分` 在终结符 `else` 上，产生式 42（`否则部分→else 语句`）与 43（`否则部分→ε`）均被选中——即**悬挂 else 二义**；
- 该二义由文法结构决定，**无法通过改写文法在 LL(1) 框架内消除**（PPT 挑战版示例自身即使用不带花括号的 `if (flag) print(a); else print(0);`）；
- **消解方式**：在预测分析表中，`否则部分` × `else` 项固定取**产生式 42**，即 **else 就近配对**（else 归属最近的未配对 if）。

> 工程替代方案（若评审要求文法层面严格 LL(1) 无冲突）：将条件语句改写为
> `条件语句 → if ( 表达式 ) 复合语句 [else 复合语句]`，强制分支使用花括号。
> 本文档采用**表内消解**，以兼容 PPT 示例写法。

### 4.10 预测分析驱动器

**数据结构**：

```cpp
// 符号栈元素：终结符 / 非终结符 / 语义动作
struct StackItem {
    enum Kind { TERM, NTERM, ACTION } m_kind;
    int m_iCode;        // 终结符/非终结符编码（§4.1、§4.2）
    int m_iSemantic;    // 语义动作编号（ACTION 时有效）
};
```

**算法**（非递归，显式栈）：

```
输入：TokenList（末尾为 #），预测分析表 M
初始化：栈 ← [#, 程序];  ip ← 0
循环直到栈空：
    X ← 栈顶;  a ← 当前输入符号
    若 X 为语义动作:  执行语义动作; 弹栈; 继续
    若 X 为终结符:
        若 X == a:  弹栈; ip 前进（取下一 Token）
        否则:       报错（含行列号）并进入错误恢复
    若 X 为非终结符:
        M[X, a] 为空 → 报错（含行列号）并进入错误恢复
        否则 P ← M[X, a];  弹栈; 将 P 的右部逆序压栈（去掉语义动作按位置插入栈中）
接受：栈空且输入已到达 #
```

**错误恢复**：报错后采用恐慌式恢复——丢弃输入符号直至遇到可继续的同步符号集合（`;` `}` `)` 或语句/声明起始符号），在预测分析表中表现为跳过当前输入符号后重新查表；保证一次编译报告多个错误且不崩溃。

3. **`ITOF` / `FTOI` 是 MiniC 扩展**：表 5-2 的 21 大类里没有「类型转换」这一类，

   （答辩时靠这两条证明「中间代码层确实插了双向转换」）。

| 关系运算 | T_INT | T_INT | T_BOOL | None | None | CMP |

| + - * / | T_CHAR | T_INT | T_INT | 整型提升 | None | ADD/SUB/MUL/DIV_4 |
| 关系运算 | T_CHAR | T_INT | T_BOOL | 整型提升 | None | CMP |
| && \|\| | T_BOOL | T_BOOL | T_BOOL | None | None | AND/OR（短路） |

| - (取负) | T_FLOAT | - | T_FLOAT | None | None | NEG_8 |

**char 的整型提升（C4 落地，见 `src/sema/semantic.cpp` 的 `IsNumeric`）**：
`char` 参与算术与关系运算时按 `int` 处理（C 语义的整型提升），结果类型分别为 `T_INT` / `T_BOOL`，
与 `int` 混算时按上表 `T_INT` 一行套用，与 `float` 混算时先提升到 `float`。
`bool` **不参与**算术与关系运算（上表 `&&`/`||`/`!` 之外无 `T_BOOL` 操作数行），
对 `bool` 做算术报 `arithmetic operands must be numeric`，做关系报 `relational operands must be numeric`。
实现上 `char` 数组元素占 1 字节（`movb` 写 / `movsbl` 符号扩展读），`char` 变量占 4 字节（`movl`），
两侧都当整数用，因此目标代码层对 char 运算无需任何特殊处理。

**常量折叠（C4 落地，见 `src/sema/ir.cpp` 的 `IRGenerator::FoldBinary`）**：
`+ - * /` 与六个关系运算符在**两侧都是编译期常量**时直接求值，不生成四元式，
按上表同一套 Promote 规则定结果类型（任一操作数为浮点则整体按浮点求值）。
三条边界**故意不折叠**：

| 情形 | 理由 |
|---|---|
| 除数为 0 | 编译期算出 `Inf` 会把「运行时除零」变成「静默的错结果」，改变程序可见行为 |
| 整型结果越界（`> 2147483647` 或 `< -2147483648`） | 交给运行时按 x86 `addl` 自然回绕，与未折叠时逐位一致 |
| `&&` / `\|\|` | 短路有副作用语义（右侧可能不执行），必须保留 `Q_JNT` / `Q_JT` 分支 |

**`print` 的换行语义（2026-10-27 变更）**：`print` **不追加换行**，只输出值本身。
`print(a); print(b);` 在同一行输出 `ab`；要换行必须显式写 `print('\n');`（词法的
`ScanCharConst` 支持 `\n \t \r \0 \\ \' \"` 六个转义）。三张格式串在
`src/codegen/codegen.cpp` 收尾处，分别是 `.LCfmt_i: .string "%d"`、`.LCfmt_f: "%g"`、`.LCfmt_c: "%c"`。
变更是为了让「一行输出多个值」成为可能——旧版格式串把 `\n` 焊死在转换符后面，
无论怎么写都只能每个值独占一行。

**语义阶段的静态检查范围（2026-10-27 补充）**：

| 检查项 | 结论 | 报错原文 |
|---|---|---|
| 函数实参个数 | **检查** | `function '<名>' expects N argument(s), but M given` |
| `void` 函数带值返回 | **检查** | `void function '<名>' cannot return a value` |
| 非 `void` 函数裸 `return;` | **检查** | `non-void function '<名>' must return a value` |
| `int` 函数返回 `float` | 只告警（Q9 截断） | `implicit conversion from float to int (truncated, Q9)` |
| 顶层（函数体外）裸 `return;` | **不检查** | — |
| 数组下标越界 | **不检查** | — |

实参个数需要**两遍**：`SemanticAnalyzer::Analyze` 先调 `CollectSignatures(root)` 收集全部函数签名，
再 `Visit(root)`。MiniC 允许「函数体里调用后面才定义的函数」，边遍历边登记会漏掉后向调用。

## 15. 遗留问题与边界说明

> 本章为 v4.0.1 新增，用于把设计评审中暴露的**边界与遗留事项**明确落档，避免实现阶段反复。

### 15.1 字符串常量的处置（待决策）

| 项 | 现状 |
|---|---|
| 词法 | 现行 `lexer.cpp` **能识别**字符串常量 `"..."`，`TokenType` 中有 `TOKEN_STRING` |
| 文法 | 挑战版文法**没有字符串终结符**，`print` 的参数是**表达式**，不接受字符串字面量 |
| 后果 | `print("abc");` 在词法阶段产出 `TOKEN_STRING`，在语法阶段**无产生式可匹配**，报语法错误 |

**处置选项**（须组长决策后执行）：

- **A（推荐）**：**保留** `TOKEN_STRING` 词法能力，但**不入文法**；文档明确「字符串常量为词法扩展，挑战版文法不支持」。
  `print` 仅接受表达式（数值/布尔/字符/变量）。
- **B**：删除 `TOKEN_STRING` 与 `ScanString()`，严格对齐文法。风险：现有 `tests/lex_test.mc` 含字符串内容，需同步改测试。
- **C**：扩展文法支持字符串字面量（新增终结符 + 产生式 + 编码），代价是**整套表格与预测分析表需重新生成**。

> 本文档默认按 **A** 执行，**词法同学不删字符串扫描能力**；若选 B/C 需重新评审。

### 15.2 文法层面的宽松点（须语义阶段拦截）

| 宽松点 | 文法位置 | 说明与处置 |
|---|---|---|
| 块内允许函数定义 | 产生式 28 `块项 → 声明`、6 `声明后续 → ( 形参列表 ) 复合语句` | 文法上允许 `{ int f(){...} }` 这类**嵌套函数定义**。C 语言不允许，须在**语义阶段**检查「函数定义只能出现在最外层」并报错 |
| 未检查「先声明后使用」 | 文法不含符号信息 | 须由符号表在语义阶段完成（`SearchVar` 失败即报错） |
| 未检查类型匹配 | 同上 | 须由 §8.1 类型系统表在语义阶段完成 |
| 空语句可出现在任意语句位置 | 产生式 36 `语句 → ;` | 合法，无须拦截 |

> **原则**：文法只保证**语法结构合法**，**语义合法性**一律由语义分析阶段负责。这一分工与 v3.1 §4.4 一致。

### 15.3 词法模块的缺失清单（端到端阻塞点）

> **这是当前唯一阻塞端到端跑通挑战版的问题。** 设计文档只定义「文法长什么样」，
> **不保证「输入流里存在这些词」**——Parser 只消费 `TokenList`，`Token` 中没有的类型，Parser 永远等不到。

**现行 `TokenType` 共 43 个成员**（含 `TOKEN_NONE`），即 **41 个文法终结符 + `TOKEN_NONE` + `TOKEN_STRING`**。
**缺 17 个终结符**：

| 序号 | 类别 | 缺失终结符 | 编码 | 词法行为要求 |
|---|---|---|---|---|
| 1 | 关键字 | `bool` | 003 | 入关键字表 |
| 2 | 关键字 | `char` | 004 | 入关键字表 |
| 3 | 关键字 | `print` | 009 | 入关键字表 |
| 4 | 关键字 | `true` | 011 | 入关键字表（布尔字面量） |
| 5 | 关键字 | `false` | 012 | 入关键字表（布尔字面量） |
| 6 | 界符 | `[` | 025 | 单字符界符 |
| 7 | 界符 | `]` | 026 | 单字符界符 |
| 8 | 运算符 | `==` | 036 | **双字符优先**匹配 |
| 9 | 运算符 | `!=` | 037 | **双字符优先**匹配 |
| 10 | 运算符 | `<` | 038 | 单字符（须避免与 `<=` 冲突） |
| 11 | 运算符 | `<=` | 039 | **双字符优先**匹配 |
| 12 | 运算符 | `>` | 040 | 单字符（须避免与 `>=` 冲突） |
| 13 | 运算符 | `>=` | 041 | **双字符优先**匹配 |
| 14 | 运算符 | `&&` | 042 | **双字符优先**匹配 |
| 15 | 运算符 | `\|\|` | 043 | **双字符优先**匹配 |
| 16 | 运算符 | `!` | 044 | 单字符（须避免与 `!=` 冲突） |
| 17 | 常量 | 字符常量 `'c'` | 054 | **新增扫描子程序**，支持 `'\n'` 等转义；`Token` 需增 `m_cVal` 字段 |

> **注意**：`< > !` 这三个**单字符运算符当前也不存在**（现行只认 `+ - * / =`），
> 因此需与 `<= >= !=` 一并实现，且**必须先判断双字符再回落单字符**。

**必须由词法负责人完成或确认的改动**（parser 侧不得越界修改）：

| 文件 | 改动 |
|---|---|
| `src/lexer/token.h` | `TokenType` 补 17 个成员；`Token` 增 `char m_cVal`；声明编码映射函数 |
| `src/lexer/token.cpp` | `TokenTypeToString` 补齐新成员；实现 `TokenTypeToCode` / `CodeToTokenType` |
| `src/lexer/lexer.cpp` | 关键字表补 `bool/char/print/true/false`；`ScanOperator` 改**双字符优先**；新增 `ScanCharConst`；字符分类表补 `[ ] < > ! & \| '` |
| `tests/` | 新增覆盖新终结符的词法用例；补充字符常量、双字符运算符、错误恢复用例 |

### 15.4 词法与语法的职责边界（重要）

```
词法负责：字符流 → Token 流   （保证 41 个终结符都能被产出）
语法负责：Token 流 → AST      （保证 105 条产生式能被正确匹配）
```

**两者互为前提**：预测分析表再完备，若词法不产出对应 Token 类型，语法分析必然在最基础处失败。
因此 §14 把「② 词法扩充」列为**与 ③ 编码层并列的前置阶段**，**不可跳过、不可后置**。
