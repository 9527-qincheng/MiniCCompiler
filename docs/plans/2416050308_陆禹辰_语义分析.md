## 一、任务目标

语义分析夹在语法和中间代码之间，是"前端最后一道关口"。挑战版要求：

1. **18 类 AST 节点全部有分派**。少一个节点，那类结构就会被"静默跳过"——
   程序照样编译通过，但符号表里没有它、IR 也不生成它，缺陷会拖到很后面才暴露。
2. **驱动符号表，而不是自己另建一套**。声明登记、作用域进出、查重、常量回填、
   类型检查全部走 `SymbolTable` 的既有接口（`EnterScope` / `ExitScope` / `RecVar` /
   `RecArray` / `RecConst` / `BackfillConst` / `CheckAssign`），
   语义阶段只负责"遍历 AST 并决定何时调哪个"。
3. **类型推导按 §8.1 类型系统表**。二元运算的类型提升、关系运算产出 `bool`、
   一元运算保持操作数类型、数组下标必须整型、`&&`/`||` 要求两侧为 `bool`。
4. **诊断要能定位**。每条错误/告警都带行列号，且单次运行应尽量多报，而不是遇错即停。
5. **嵌套函数必须拦截**。文法上块内允许函数定义（设计文档 §15.2 记录的宽松点），
   但 C 不允许，且会与外层同名函数生成重复汇编标号，语义阶段必须报错。

- [x] `&&` / `||` 操作数非 bool 报 `logical operators require bool operands`
- [x] 嵌套函数定义报 `function definition is only allowed at the outermost level: <名字>`
- [x] 单次运行可报多个错误（`err_multi` 一次报出 3 条）
- [x] 块内变量遮蔽合法、`bool` 作条件合法、`void` 裸 `return` 合法
