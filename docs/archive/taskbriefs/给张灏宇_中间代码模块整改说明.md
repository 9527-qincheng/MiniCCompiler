## 二、必改 1：int → float 的宽化转换没有插入 ITOF

### 现状与代码位置

| 位置 | 现状 |
|---|---|
| 赋值 `x = i;` | src/sema/ir.cpp:525-529 **只**处理 FLOAT→INT（`IsIntType(lhsT) && IsFloatType(...)` → `FloatToIntConv`） |
| 数组写 `a[i] = f;` | src/sema/ir.cpp:557-560 **只**处理 FLOAT→INT |
| 函数实参 `fx(i)` | src/sema/ir.cpp:446-453 **完全不做**类型转换 |
| 函数返回 `return i;`（float 函数） | src/sema/ir.cpp:645-650 **完全不做**类型转换 |
| 算术混合 `x + i` | src/sema/ir.cpp:341-347 **会**插 ITOF（`IntToFloatConv`，定义在 :221-226） |

**问题**：同一份 IR 里，缩小（FLOAT→INT）插 FTOI、放大（INT→FLOAT）不插 ITOF，**自相矛盾**。目标代码只要按操作数的声明类型取值（`Operand::m_type` 在 `Var()` 里是按声明类型建的），int 值被当成 float 用就会算错。

### 实测（复现命令见第五节）

| 用例 | 现状四元式 | 期望四元式 |
|---|---|---|
| `float x; int i; x = i;` | `(=, i, -, x)` | `(ITOF, i, -, _T1)` / `(=, _T1, -, x)` |
| `float g2; g2 = f(2);`（f 返回 int） | `(PARA,2,-,-)` `(CALL,f,-,_T2)` `(=, _T2, -, g2)` | 同上但 `(=, ...)` 前应有 `(ITOF, _T2, -, _T3)` |
| `float fx(float b); g2 = fx(3);` | `(PARA, 3, -, -)` | `(ITOF, 3, -, _T1)` / `(PARA, _T1, -, -)` |
| `int i; float x; i = x * 2.5;`（对照，现状**正确**） | `(*, x, 2.5, _T1)` `(FTOI, _T1, -, _T2)` `(=, _T2, -, i)` + Q9 告警 | 保持不变 |

### 怎么改

**1）赋值（:526 的 if 后面补对称分支）**

```cpp
// FLOAT ← INT：插入 ITOF
else if (IsFloatType(lhsT) && IsIntType(OperandType(val)))
{
    val = IntToFloatConv(val, a->m_loc);
}
```

**2）数组写（:557）** 同样补一条：`IsFloatType(elemT) && IsIntType(OperandType(val))` → `IntToFloatConv`。

**3）返回值**：给 `IRGenerator` 增加一个「当前正在生成的过程」成员（在 `GenFuncDef` 里赋 `proc`、结束时清空），`RETURN` 时按 `proc->m_retType` 判断是否需要宽化。`ProcEntry` 已经有 `m_retType`（src/symbol/symbol.h:73），不用改符号表。

**4）函数实参——这一条要先补信息**：`ParamEntry`（src/symbol/symbol.h:78-83）只有 `m_type` 和 `m_iParamPos`，**没有「属于哪个过程」的字段**，所以现在拿不到「第 i 个形参是什么类型」。两个选择：

- (a) 和符号表组（焦艺浩、李钊杰）确认后，给 `ParamEntry` 加过程归属字段，并在 `docs/interface.md` 登记（属接口变更，要和相关组对齐）；
- (b) 本轮先不做，在 PR 描述里明确标注「实参宽化转换待补」。

**建议选 (a)**，否则 `fx(i)` 这类调用在目标代码里仍然会错。

## 三、必改 2：`&&` / `||` 没有真正短路右操作数

### 现状与代码位置

src/sema/ir.cpp:272-273 在进入逻辑分支**之前**，先把左右两个操作数都求值完了：

```cpp
Operand lo = EvalExpr(bin->m_children[0]);
Operand ro = EvalExpr(bin->m_children[1]);   // ← 右操作数的四元式在这里就已经发出去了
...
if (op == TokenType::TOKEN_AND || op == TokenType::TOKEN_OR)   // :284 逻辑分支在最后面
```

于是 :292 的 `Q_JZ` / :302 的 `Q_JNZ` 只用来**挑结果**，右操作数的求值与其副作用（函数调用、除法、数组写）早就发生了。commit message 和 interface.md 都写了「短路求值」，实际语义不符。

### 实测

用例 `q = (i != 0) && (10 / i > 1);`，`--dump-quads` 实际顺序：

```
(!=, i, 0, _T5)
(/, 10, i, _T6)      ← 右操作数在跳转之前就算完了：i == 0 时这里会除零
(>, _T6, 1, _T7)
(JZ, _T5, -, L1)
(=, _T7, -, _T8)
(JMP, -, -, L2)
(LABEL, L1, -, -)
(=, 0, -, _T8)
(LABEL, L2, -, -)
```

期望顺序（右操作数只在左边为真时才求值）：

```
(!=, i, 0, _T5)
(JZ, _T5, -, L1)     ← 跳过右操作数
(/, 10, i, _T6)
(>, _T6, 1, _T7)
(=, _T7, -, _T8)
(JMP, -, -, L2)
(LABEL, L1, -, -)
(=, 0, -, _T8)
(LABEL, L2, -, -)
```

`||` 完全同理（`(JNZ, ...)` 必须出现在右操作数四元式之前）。

### 怎么改

把「是否逻辑运算」的判断**提到 :272 之前**，右操作数改成「进分支之后再求值」：

```cpp
if (op == TokenType::TOKEN_AND || op == TokenType::TOKEN_OR)
{
    Operand lo = EvalExpr(bin->m_children[0]);      // 只先算左边
    ...
    EmitIR(QuadOp::Q_JZ, lo, Operand(), Operand::Label(lMid), loc);
    Operand ro = EvalExpr(bin->m_children[1]);      // ← 挪到这里
    EmitIR(QuadOp::Q_ASSIGN, ro, Operand(), Operand::Temp(tIdx, TOKEN_BOOL), loc);
    ...
}
```

注意 :274-277 那个「任一操作数为 OP_NONE 就放弃」的检查也要跟着调整（改成分别检查 lo / ro）。

## 四、建议一并处理（不阻塞合入，但建议同批修）

1. **`Q_INDEX` 取值与存值共用同一个操作码**：取值是 `(INDEX, 数组, 下标, 临时量)`（src/sema/ir.cpp:422），存值是 `(INDEX, 值, 下标, 数组)`（:561）。目标代码只能靠操作数位置猜是读还是写，很容易错。建议拆成 `Q_LOAD` / `Q_STORE`——改 `ir.h` 枚举属接口变更，请先和组长、王逸凡对齐后一起在 `docs/interface.md` 登记。
2. **语法/语义报错后仍会生成 IR**：src/main.cpp:213 已经用 `g_ErrorList.empty()` 把语义挡在门内，但 :225-227 的 `ir.Generate(root)` 和 :247 的 codegen 是**无条件执行**的。源码含非法字符（如 `%`）时，残缺 AST 仍会产出半截四元式，目标代码有崩的风险。建议照语义那样包一层 if——这条要动 `main.cpp`，动手前先和组长确认口径。
3. **`.sym.txt` 里浮点常量显示被截断**：`float x; x = 2.5;` 时符号表打印 `2.5 : FLOAT = 2`。你在四元式里用原文（`2.5`）打印是对的，符号表那侧是整数域存储的遗留问题——反馈给焦艺浩/李钊杰即可，不用在 IR 里绕。
4. **补一条全特性黄金基线**：建议顺手加一个覆盖「int/float 混合 + 数组 + 函数（含返回/实参）+ if-else + while + 短路 + print」的 `.mc` 用例，把期望四元式固化成回归基线。写法可以参考刚合入的 `tests/run_symtab_tests.ps1`（见 PR #15）。
