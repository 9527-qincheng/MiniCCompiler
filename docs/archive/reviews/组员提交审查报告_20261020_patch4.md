### 3.1 两个新文件都只有 1 个换行符 → 整份文件变成注释

实测（`git cat-file blob` 取原始 blob，不受 checkout 影响）：

后果，逐条推：

- **`semantic.h`**：第 1 行是 `#pragma once// ====...`（`#pragma once` 在第 0–11 字符，`//` 在第 12 字符）。`//` 之后到第 1549 字符**全被注释掉**——包括 `#include "parser/ast.h"`、`#include "symbol/symbol.h"` 和整个 `class SemanticAnalyzer { ... }`。

规律很清楚：**他一直在用 GitHub 网页版编辑器写代码。** 网页 `<textarea>` 对含中文的长文本 + 浏览器/输入法组合，很容易在粘贴时把换行吃掉；而且这轮他还额外掺进了 `8` `33` `7` 这些数字 —— 那是**从渲染后的 Markdown 页面上复制时，把行号也一起复制进来了**（我方案文档里代码块是带行号显示的）。

patch-4 的 `main.cpp` 里 `8#include` 和 `33#include` 前面的 `8` 和 `33`，正好对应方案文档中那两行的行号位置。

**所以整改重点不是"再改一遍代码"，而是"换一条上传通道"。**
