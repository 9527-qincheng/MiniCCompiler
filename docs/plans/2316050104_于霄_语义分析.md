## 一、任务目标

与陆禹辰、陕海波共同承担语义模块。本人负责**声明与作用域**这一侧——
这是符号表能否被正确填充的决定性一环：

1. **声明登记**。`VisitDecl` 走 `RecVar`、`VisitArrayDecl` 走 `RecArray`、
   `VisitFuncDef` 走 `RecProc` + 逐个 `RecParam`。
   登记的时机、位置（行:列）必须指向**声明处**而不是使用处。
2. **作用域进出**。块语句进入时 `EnterScope(SCOPE_BLOCK)`，退出时 `ExitScope()`。
   必须保证**每条路径都成对**——一旦漏掉一次 `ExitScope`，后续所有声明都会
   落到错误的作用域里，`.sym.txt` 的 `scope N` 全错，而程序照样编译通过。
3. **查重交给符号表**。`RecVar` 内部只看当前作用域（`curMap.find`），
   语义阶段不要自己再去全局表里查一遍——否则内层遮蔽会被误报成"重复声明"。
4. **形参与局部变量的冲突**。形参属于函数体作用域，函数体内再声明同名变量必须报
   `duplicate variable`，这条最容易漏。
5. **变量遮蔽必须允许**。内层块声明与外层同名的变量是合法的，
   退出内层后外层变量恢复可见——这条要能被明确验证，而不是"恰好没报错"。

## 三、验收标准

- [x] 变量/数组/函数/形参四类声明分别走 `RecVar` / `RecArray` / `RecProc` / `RecParam`
- [x] `EnterScope` 与 `ExitScope` 在所有代码路径上成对，全局层永不被弹出
      （`ExitScope` 有 `m_varScopeStack.size() > 1` 保护）
- [x] 同一作用域重复声明报 `duplicate variable '<名字>'`
- [x] **形参与函数体内局部变量重名**报 `duplicate variable 'x'`（`err_dup_param` 验证）
- [x] **内层遮蔽外层合法**（`ok_scope_shadow` 验证：`{ int a; a = 2; print(a); }` 之后
      外层 `a` 仍为 1，退出码 0、无诊断）
- [x] `int a; int a;` 报重复声明（`err_duplicate` 验证）
- [x] 声明的 `@line` / `@col` 指向声明处
- [x] 12 例语义回归全绿，已挂进 `build.bat test`
