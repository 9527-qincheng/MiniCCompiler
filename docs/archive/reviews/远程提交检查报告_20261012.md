### 3.3 发现的问题

#### 🔴 问题 1（致命）：类名冲突导致链接失败

| 文件 | 类名 |
|---|---|
| `src/symbol/symbol.h`（原有） | `class SymbolTable` |
| `src/symbol/symbol_table.h`（新增） | **`class SymbolTable`** |

两个同名类各有 .cpp 实现，而 `CMakeLists.txt` 使用 `GLOB_RECURSE` 自动收集所有 `.cpp`：

```cmake
file(GLOB_RECURSE MINIC_SOURCES CONFIGURE_DEPENDS "${CMAKE_CURRENT_SOURCE_DIR}/src/*.cpp")
```

→ 两个 `SymbolTable::SymbolTable()` 等符号同时入链 → **重复定义**。

**实测证据**：
- 9 个源文件**单独编译全部通过**（`-c` 逐个 OK）
- **整体链接失败**：`collect2.exe: error: ld returned 1 exit status`
- 单独链接 `symbol.cpp` + `symbol_table.cpp` 即失败

#### 🔴 问题 2：绕过冻结的接口契约（设计文档 §7.3）

| 本次上传 | §7.3 契约 |
|---|---|
| `enterScope()` | `EnterScope(ScopeType t)` |
| `exitScope()` | `ExitScope()` |
| `insertVar(const VarInfo&)` | `RecVar(name, type, line, col)` |
| `lookupVar(name)` | `SearchVar(name)` |
| 缺 | `BackfillConst` / `CheckAssign` / `DumpSymTab` |

§2.4 规定「模块接口冻结，变更需全员评审」，此变更未走流程。

#### 🔴 问题 3：头文件路径错误

`tests/main_test.cpp` 写 `#include "symbol_table.h"`，但文件在 `src/symbol/` 下：

```
tests/main_test.cpp:2:10: fatal error: symbol_table.h: No such file or directory
```

#### 🔴 问题 4：两个 `main()` 冲突

`tests/main_test.cpp` 与 `src/main.cpp` 都有 `int main()`；且前者用了 Windows 专有的 `system("pause")`。

#### 🟡 问题 5：`main` 分支内容比 `dev` 旧

`main` 的 `parser.cpp` 仍是**全 TODO 骨架**，`test.ast.txt` 仍为占位：

```
// AST dump: parser core not implemented yet (TODO)
```

而 `dev` 早已实现完整递归下降。本次上传使 `main` **回退**。

### 3.4 可取之处

- 作用域栈 `varTableStack` + `currentScope`，查找自内向外，符合 C 块作用域语义；
- 查重报错信息清晰；
- 错误状态管理（`lastError` / `clearError()`）思路干净；
- 覆盖 `int/float/char/bool` 四种类型，与挑战版一致。

这些思路**可移植进既有 `SymbolTable`**。

### 3.5 处理结果

**❌ 未合入**，已生成修改意见：《给yvechu的说明_symbol_table问题.md》
